## 1. 개요

### 1.1 비전
가족 구성원 누구나 언제 어디서든 우리 집의 일정과 돈 흐름을 한곳에서 확인하고 함께 관리하는 가족 전용 공간.

### 1.2 문제 정의
- 가계부·일정·고정 지출·자산·경조사비가 각자의 엑셀, 메모장, 개별 앱에 흩어져 있다.
- 한 사람이 관리하면 나머지는 현황을 모르고, 여럿이 하면 중복과 누락이 생긴다.
- 기존 가계부 앱은 개인 중심이라 "가족 공유"와 "가족 안의 개인 공간"을 동시에 주지 못한다.

### 1.3 설계 원칙
1. **수동 입력 전제** — 은행 API·마이데이터·오픈뱅킹 연동은 하지 않는다(영구 제외). 입력 마찰은 UX로 푼다: 기본값(오늘, 마지막 사용 자산), 반복/할부 자동 생성, 토글형 선택지, 3탭 이내 입력.
2. **가족 공유 + 개인 프라이버시 공존** — 자산·가계부·월 예산은 각각 `[가족]` / `[🔒 개인(나만 보기)]` 탭을 가진다. 개인 데이터 차단은 화면이 아니라 **DB의 RLS 정책**으로 강제한다.
3. **구성원 색상 = 공통 식별 체계** — 온보딩에서 고른 색이 아바타·캘린더·가계부·축의금 전반에서 그 사람을 나타낸다.
4. **모듈별 편집 권한** — 대표가 구성원×모듈 단위로 편집 권한을 토글한다. 꺼진 모듈은 보기 전용. 단, 개인 범위 데이터와 메시지는 권한과 무관하게 본인이 쓴다.
5. **금융 집계의 신뢰성** — 거래가 자산 잔액을 자동 증감(부채는 부호 반전)하고, 수정·삭제는 정확히 역산한다. 삭제는 소프트 삭제.

### 1.4 비목표
- 금융기관 연동 전반(영구), 결제 문자 파싱(영구)
- 네이티브 앱 스토어 배포(PWA로 대체), 다국어(한국어 전용), 투자 포트폴리오 분석

## 3. 기능 요구사항

### 3.1 인증
- 이메일 가입: 이름, 생년월일(필수 — 캘린더 생일 자동 표시용), 이메일, 비밀번호(영문+숫자 8자 이상, 확인 입력), 휴대폰(선택), 약관 동의(이용약관·개인정보 필수, 마케팅 선택, 전체 동의). 성별은 받지 않는다.
- 이메일 인증 필수. 인증/재설정 콜백은 코드 교환 방식이며, 리다이렉트 주소는 요청 Host 헤더로 복원한다(0.0.0.0 바인딩·프록시 환경 대응, `next` 파라미터는 내부 경로만 허용).
- 비밀번호 재설정: 메일 링크 → 복구 세션 확인(만료 시 재요청 안내) → 변경 후 세션 종료·재로그인 유도. 이메일 존재 여부가 드러나지 않는 문구 사용.

### 3.2 가족 온보딩
- 로그인 후 가족이 없으면 온보딩으로 강제 이동(가족이 있으면 온보딩 접근 시 홈으로).
- **가족 만들기**: 가족 이름 → 내 호칭·색상 → 초대코드 발급 화면(코드/링크 복사).
- **가족 참가**: 코드 6자리(혼동 문자 제외, 7일 유효, 재발급 가능) → **가족 미리보기**(이름·인원 확인 후 참가 확정) → 호칭·색상.
- 초대 링크 `/invite/[코드]`: 코드를 쿠키(10분)에 담아 로그인/가입을 거쳐도 이어지게 한다.
- 호칭: 선택지(아빠/엄마/아들/딸) 기반 검색 드롭다운. 색상: 24색 팔레트, **기존 구성원이 쓰는 색은 빗금 표시 + 선택 차단**(서버 검증 포함).
- 코드 조회·참가 시도는 분당 5회 제한(무차별 대입 방지).
- 역할: owner / member / viewer (+ admin 예비). 가족 해체는 owner만 — 가족 이름 입력 확인 후 전체 데이터 삭제(cascade).

### 3.3 자산
- 그룹 10종: 현금/은행/체크카드/신용카드/저축/투자/마이너스 통장/대출/보험/기타. 신용카드·마이너스 통장·대출은 **부채**.
- 상단 요약: `순자산 = 자산 − 부채` (자산은 파랑, 부채는 빨강. 모바일은 3행 스택, 라벨 고정폭으로 금액 열 정렬).
- 탭: `[가족 자산]`(기본) / `[🔒 내 자산]`. 개인 자산은 명의자 본인만 조회·수정·삭제. 가족 집계(대시보드·통계·월 예산)에는 공동 자산만 포함.
- 등록 항목: 공개 범위(🏡 공동 / 🔒 나만 보기 — 나만 보기는 명의자 자동 본인) / 그룹 / 기관(국내 은행·증권·카드·보험 프리셋 자동완성 + 자유 입력) / 이름 / 금액(₩ 기호가 숫자에 붙어 이동) / 명의자(선택) / 저축 그룹 한정 만기일(선택, 카드에 표시) / 메모.
- 금액 수정 시 기준일 자동 갱신("N월 N일 기준" 표시) + 잔액 변경 이력 적재(자산 추이 그래프 재료).
- 그룹별 섹션 + 소계, 자산 카드에 로고 자리(기관 첫 글자 + 그룹 색).
- 카드 클릭 → 해당 자산으로 필터된 가계부로 이동(개인 자산이면 개인 탭으로). 수정은 "자산 수정" 모드 토글 후 카드 선택.

### 3.4 가계부
- 탭: `[가족 가계부]` / `[🔒 개인 가계부]`. 개인 거래는 작성자만 보고 관리하며, 모듈 권한과 무관하게 기록 가능.
- 거래 입력(모달, 모바일 하단 ➕에서 직행): 유형(지출/수입/이체) → 날짜 + **반복/할부 버튼** → 금액 → 카테고리 그리드 → 자산 → 구성원(기본 본인) → **내용(지출·수입 필수)** → 메모. 마지막 사용 자산 기억.
- **할부**: 개월 수(2~60) 입력 → 총액을 N등분해 매달 1건씩 생성, 내용에 "(회차/N회차)" 부가, 끝전은 마지막 회차. 지출 전용, 버튼은 연파랑 "N개월 할부"로 표시.
- **반복**: 매일/주중/주말/매주/2주/4주/매월/월말/2·3·4·6개월/1년 — 주기별 합리적 범위를 사전 생성(일 단위 약 3개월, 주 단위 약 6개월, 월 단위 1년, 연 단위 2회). 버튼은 코랄색 + 주기명.
- 반복/할부 묶음은 그룹 ID로 연결 — 수정 모달에서 "이 거래만 / 묶음 전체" 삭제 선택.
- 자산 잔액 자동 반영: 지출·수입·이체(보내는/받는 자산 동시) 모두 트리거로 증감, 소프트 삭제·수정 시 역산. (주의: 삭제 필터는 RLS가 아닌 조회 쿼리에서 — RLS에 넣으면 소프트 삭제 UPDATE가 자기 반환 조건에 걸려 실패한다.)
- **이체 규칙**: 가족 탭 — 보내는 자산은 공동만, 받는 자산은 공동 + 전 구성원의 개인 자산(🔒 구성원·기관·이름만 최소 노출, 잔액 비공개 — 용돈 이체용). 개인 탭 — 보내는 자산은 내 개인만, 받는 자산은 내 개인 + 공동(🏡 표시).
- 카테고리: 1단계(대분류만). 가족 생성 시 기본 템플릿 자동 시드(지출 16·수입 8, 이모지+색상). 관리 모달: 추가/수정/삭제(기존 거래는 "미분류"로 유지) + 드래그 핸들 정렬(외부 라이브러리 없이 포인터 이벤트).
- 목록: 월 네비게이션 + 월 요약(수입/지출/합계), 일별 그룹 헤더(수입/지출/합계 라벨), 행 = 카테고리 이모지 · 내용(굵게) · 카테고리·메모·구성원·자산 · 금액. 자산 필터 드롭박스(현재 탭의 자산만).
- 모바일 헤더: 제목 / 가족·개인 탭(전체 폭) / 자산 드롭박스 / 버튼 3등분 — 각 한 줄.

### 3.5 월 예산
- 개념: 청구서 관리가 아니라 **월 예산표**다. `{N}월 예산(수입 계획) − {N}월 고정비 = 남는 금액`을 관리한다.
- 탭: `[가족 예산]` / `[🔒 내 예산]`. 예산값도 가족 공용과 구성원 개인을 분리 저장. 개인 항목은 작성자만 관리(권한 무관).
- 요약 카드: 예산(클릭 인라인 수정, Enter 저장) / 고정비 합(−표시) / 남는 금액(음수면 빨강) + 납부 진행(완료/미납) 보조줄. 모바일은 3행 스택 + 라벨 폭 정렬.
- **용도별 요약 / 자산별 요약** 카드 2열: 용도(고정비·용돈·적금·대출이자·육아·기타) 합계, 자산별 분배 합계(어느 통장에 얼마 배정되는지).
- 항목 등록: 용도 칩 / 이름 / 금액 / 구분(공동·구성원, 개인 탭은 자동 본인) / 주기(매월·2·3·4·6개월·매년) / 납부일(1~31일·말일) / **자산(필수 — 분배 대상, 현재 탭 범위의 자산만)** / 시작·종료일 / 메모 / 비활성 토글.
- 발생분: 페이지 로드 시 이번 달+다음 달 치를 지연 생성(cron 불필요). **시작일이 속한 달부터 생성**(등록 시점에 납부일이 이미 지났어도 그 달 발생분을 만든다).
- 납부 체크: 체크 → 날짜 확인 모달(기본 납부 예정일, 수정 가능) → 상태 기록. **가계부에 자동 기록하지 않는다.** 체크 해제, 이번 달 건너뛰기/되돌리기 지원. 예정일 경과 시 "미납 D+N" 뱃지, 지난달 미납은 "밀린 납부" 섹션.
- 목록: 구성원별 섹션(공동은 마지막) + 소계, 이번 달 발생 없는 항목(격월·연납·비활성)은 별도 섹션.

### 3.6 캘린더
- 월 그리드(6주 42칸): 일요일 빨강·토요일 파랑, 오늘 원형 강조, 앞뒤 달 흐림. 일정 칩 최대 3개 + "+N", 칩 클릭 → 수정.
- 하단 3카드: 선택한 날(기본 오늘) / 이번주 / 다가올 일정(이후 30일 5건).
- 일정: 제목 / 설명 / 종일 토글 / 시작·종료 날짜·시간 / 장소 / 반복 토글(매일·매주·매월·매년 + 종료일) / 참석자 체크리스트.
- **반복은 행을 만들지 않고 표시 시점에 전개**한다(무한 반복도 행 1개). 반복 일정 삭제는 시리즈 전체.
- **색상 자동 규칙**(선택 UI 없음): 참석자 1인 → 그 사람 색 / 그 외 → 등록자 색. 저장 시마다 재계산.
- 자동 표시: 🎂 가족 생일(가입 생년월일 기반, 나이 병기, 기본 ON) / 💸 월 예산 납부일(기본 OFF, 클릭 시 월 예산으로) / **대한민국 공휴일**(대체공휴일 포함 연도별 내장 데이터, 칸 배경 틴트 + 빨간 날짜 — 매년 말 다음 해 데이터 추가 운영).
- 구성원 필터 칩(기본 전체 선택). 칩 글자색은 멤버 색의 명도를 보정해 밝은 색도 가독 확보.

### 3.7 축의금
- **관계인(사람/집안) 중심 장부**. 관계인: 이름 / 관계(가족·친척·친구·직장·이웃·기타) / 소속 / 누구의 지인인지(구성원 색점, 미지정은 "공통" 뱃지) / 메모.
- 기록: 관계인 검색 선택(**없으면 그 자리에서 즉석 추가** — 이름+관계만) / 보냄·받음 토글 / 유형(💍결혼 🕊️장례 🎂돌 🎉생일 🎊개업 🧧명절 기타) / 금액(비현금은 0+메모) / 날짜 / 참석 체크 / 메모.
- 화면: 요약(보낸/받은/수지 + "올해만" 토글) · 탭(관계인/최근 기록) · 이름·소속 검색 · 관계 필터(전체 버튼 포함).
- 관계인 카드: 누계(보냄·받음), 마지막 기록일. 클릭 → 상세 모달(수지 + 전체 타임라인 + 기록 추가 + 관계인 수정). 삭제 시 "기록 N건과 함께 삭제" 경고.
- 가계부와 연동하지 않는다(독립 장부).

### 3.8 메시지
- 목록 구조: **나에게(메모)** 상단 고정 → **가족 전체방**(가족 이름, 전원 공유) → 구성원 1:1. 마지막 메시지 미리보기 + 안읽음 수 뱃지.
- 1:1 대화는 당사자만 조회 가능(같은 가족이라도 남의 대화는 DB에서 차단). 메모는 본인만. 메시지는 모듈 권한과 무관하게 전 구성원 사용.
- **Supabase Realtime**으로 수신·수정·삭제 실시간 반영. 대화창을 열어두면 자동 읽음 처리.
- 입력: Enter 전송 / Shift+Enter 줄바꿈(한글 조합 중 오전송 방지), 내 메시지 클릭 → 수정("(수정됨)" 표시)/삭제. 데스크톱 2패널, 모바일은 목록↔대화 전환.

### 3.9 통계
- 진입: 가계부·자산 헤더의 "통계" 버튼 → `/stats` 단일 페이지, `[가계부]/[자산]` 탭.
- 가계부 탭(+ 가족/개인 토글, 월 네비게이션): 카테고리별 지출 도넛(상위 7 + 그 외, 카테고리 색, 중앙 총지출, 순위 리스트) / 구성원별 지출 가로 막대(멤버 색 — 개인 토글 시 생략) / 월별 수입·지출 막대(최근 6개월).
- 자산 탭(+ 가족/내 자산 토글): 자산 구성 도넛(부채는 도넛에서 제외하고 리스트에 음수 표기) / 순자산 추이 3선(자산·부채·순자산 — 잔액 이력의 월말 스냅샷).
- 고정 시리즈 색은 색각이상 검증을 통과한 조합(파랑 #4E7DC4 / 코랄 #E8645B / 보라 #8458B3). 축 금액은 "350만/1.2억" 축약. 전 차트 호버 툴팁.

### 3.10 대시보드
- 2구역: **좌(2/3)** 가계 요약(이번 달 수입/지출/남은 금액) → 도넛 위젯 2열(카테고리별 지출·자산 구성, "자세히"→통계) → 고정비·일정·최근 거래 위젯 3열 / **우(1/3)** 우리 가족(실명+호칭+대표 뱃지, 초대코드 복사·링크·재발급) + 확장 여백.
- 위젯 데이터: 다가오는 고정비(7일 내+미납, D-day 뱃지, 가족 항목만) / 이번 주 일정(반복 전개 + 생일 포함, 7일) / 최근 거래 5건(가족 거래만, 미래 날짜 제외 — 단 월 요약에는 이번 달 미래분 포함).
- 1인 가족이면 초대 안내 배너(닫기 영구). 인사말 "{실명} 님, 어서 오세요 😊".

### 3.11 설정
- 내 정보: 실명(메인)·호칭·이메일 표시, **내 색상 변경**(타인 사용 색 빗금), 로그아웃.
- 대표 전용: **구성원 권한**(구성원×모듈 칩 토글, 즉시 저장) / **가족 해체**(이름 입력 확인 + 서버 owner 검증).

## 4. 비기능 요구사항

- **반응형**: 모바일 우선. 하단 탭(홈·가계부·➕·캘린더·더보기) + 중앙 FAB, 데스크톱 사이드바(소통/가계/일상/보관 그룹). 요약 수치는 모바일에서 행 스택 + 라벨 고정폭 정렬 패턴.
- **보안**: 모든 테이블 RLS. 재귀 방지용 security definer 헬퍼(`is_family_member`, `can_edit_module` 등)로 정책 구성. 개인 범위는 `is_private + 본인 확인` 패턴 통일. 민감 작업(해체·권한)은 서버에서 재검증.
- **데이터**: 금액 numeric(14,2)·KRW 고정. 거래 소프트 삭제. 잔액·이력은 트리거 유지.
- **디자인**: 로고 팔레트 기반 웜톤(크림 배경 #FBF6EF, 코랄 주색 #E8645B) HSL 토큰, Pretendard Variable 자체 호스팅, shadcn/ui 스타일 컴포넌트(+자체 Modal·SelectBox·콤보박스), 파비콘/매니페스트(홈 화면 추가 대응).

## 5. 기술 아키텍처

- **프론트**: Next.js 15 App Router(RSC 중심), 서버 컴포넌트에서 데이터 조회 → 변경 후 `router.refresh()` 패턴. 폼 검증은 인증 화면만 react-hook-form+zod, 나머지는 경량 상태. 차트는 Recharts. 상태 라이브러리(Zustand 등)는 필요해질 때 도입.
- **백엔드**: Supabase — PostgreSQL(RLS)·Auth(이메일 확인)·Realtime(메시지). Storage/Edge Functions는 파일함·알림 단계에서 도입.
- **스케줄 없는 생성 전략**: 월 예산 발생분은 페이지 로드 시 지연 생성, 가계부 반복은 저장 시 사전 생성, 캘린더 반복은 표시 시 전개 — cron 의존 없음(알림 도입 시 pg_cron 승격).

### 데이터 모델(요약)
profiles(가입 트리거 복사) · families · family_members(역할·호칭·색) · member_permissions(모듈 권한) · invite_attempts(제한) · assets + asset_balance_history · categories(시드) · transactions(반복 그룹·개인 플래그) · fixed_costs + fixed_cost_occurrences + fixed_cost_amount_history · budget_settings + personal_budget_settings · events + event_attendees · contacts + gift_records · messages + message_reads

### 주요 RPC
가족 생성/코드 미리보기(사용 색 포함)/코드 참가/코드 재발급/가족 해체 · 발생분 생성/납부/납부 취소/건너뛰기 · 이체 대상 목록(개인 자산 최소 노출) · 모듈 권한 판정

## 7. 환경·운영 체크리스트

- **로컬(WSL 9p 마운트) 제약**: 심볼릭 링크·일부 rename 불가 → `.npmrc bin-links=false` + 스크립트에서 next 바이너리 직접 호출, 패키지 추가는 `--package-lock-only` 후 `npm ci`. Next trace 파일 유령화 → `NEXT_TRACE_SPAN_THRESHOLD_MS` 상시 주입 + 로컬만 `NEXT_DIST_DIR=build`(Vercel은 항상 `.next`). 권장: docker compose(web, named volume)로 개발.
- **Vercel**: `NEXT_PUBLIC_SUPABASE_URL/ANON_KEY`를 Config 타입으로(Production 체크), 저장 후 Redeploy 필수.
- **Supabase**: Auth URL Configuration에 배포 도메인 Site URL + `/auth/callback` Redirect 등록(누락 시 메일이 localhost로). 기본 메일러는 시간당 2통 — Resend 등 커스텀 SMTP 연결. Realtime publication에 messages 등록. 마이그레이션은 SQL Editor(postgres 역할)에서 적용.
